# Texts in several languages

A game shows its players texts: a score, a hint, the end screen's message, the labels of its
menus. Written straight into the scripts, they are in one language. Kept in translation files,
the same game shows them in English to one player and in Portuguese to another.

## Translation files

They go in the game's `locales/` folder, one per language, named for it: `locales/en.json`,
`locales/pt.json`, `locales/pt_BR.json`. Each is a JSON object of keys and the texts they stand
for:

```json
{
  "hud.coins": "Coins {count}/{total}",
  "hud.hint": "Grab every coin, then reach the flag!",
  "over.win": "You win!"
}
```

A key is any name you like; words joined by dots keep them in order (`hud.coins`, `menu.credits`).
A text names the values put into it in braces (`{count}`). A long text may be a list of lines,
which are joined with line breaks: `"credits": ["Made by Ana", "Music by Rui"]`.

English is the one every other language falls back to, so `en.json` has every key; a translation
has the keys it translates, and a key it lacks shows in English.

The templates come with a `locales/en.json`, and the platformer's (`games/platformer/locales/`) is
a full example.

## Showing a text

`I18n.t` gives the text of a key in the language in use, with its values filled in:

```ruby
UI.text(I18n.t("hud.coins", count: @coins, total: @total), x: 20, y: 40, size: 28, color: :gold)
GameMenu.instance.finish(I18n.t("over.win"))
```

Each value is shown as its `to_s`. A number with a set number of decimals is formatted first:
`I18n.t("hud.best", seconds: format("%.1f", @best))`. Keep a whole sentence in one text, values
and all, rather than gluing pieces together: another language may want the values elsewhere, or
a different word for one and for many (`"{place}: 1 other player"` and
`"{place}: {count} other players"` are two keys).

A key no file has a text for shows as itself (`hud.coins`), so a missing text is easy to spot on
the screen.

## The language

`I18n.locale` is the language texts are shown in, as a Symbol (`:en`). It starts as the player's:
the language chosen in RedGem's settings, else the system's, when the game has a translation file
for it; otherwise the language RedGem shows its own texts in (English when it has none in the
player's). A game may offer a choice:

```ruby
I18n.available_locales    # => [:en, :pt]: the languages the game has files for
I18n.locale = :pt         # from now on, in Portuguese
```

A text already looked up keeps its language: `GameMenu`'s labels are looked up as the menu is
added, so pick the language before adding it (in the scene script's `setup`, say).

## The engine's own texts

The labels of `GameMenu` (Play, Quit, Play again, Resume, Restart, Paused) come from the engine,
in the player's language. A game's files may change them or translate them, with the same keys:

```json
{
  "game.menu.play": "Start",
  "game.menu.resume": "Continuar"
}
```

The keys are `game.menu.play`, `game.menu.quit`, `game.menu.play_again`, `game.menu.resume`,
`game.menu.restart` and `game.menu.paused`. A text is looked for in the game's files in the
language in use, then in the game's English, then among the engine's texts, then the key itself
is shown.

## What is read, and what is not

Translation files travel with the game: builds, Android packages and dedicated servers carry the
`locales/` folder like the rest. They are read once, when the game's scripts start. Only files
named `<language>.json` are read (a language's name is letters, digits, `-` and `_`), none larger
than 1 MB and none reached through a symbolic link. A file that is not a translation file (broken
JSON, or a value that is neither a text nor a list of lines) is left out whole: the log says which
file and why, and the game goes on with the others.

On a dedicated server each room has its own `I18n.locale`. A text a server sends players, such as
the reason a join was turned down, is in the server's language: a game that wants it in each
player's sends a key and lets the player's machine look it up.
